# Interface guidance

## Current experience

`/explore` is a study journal: one prominent visual beside a compact explanation and checked execution state. The cover offers one actual recorded example, with secondary destinations under **More examples**. Choosing an example closes the disclosure; Escape closes it and returns focus. Preserve each option’s live, recorded or prepared label.

Printed computation is checked; handwritten explanation is model-authored or explicitly prepared. Source readings, assumptions, model actions, history, memory and deletion belong in labeled disclosures, not a competing dashboard. **How it was made** exposes actual review status, calls and timing; missing review is never approval. [Journal details](UI_DOT_JOURNAL.md).

## Interaction rules

- Keep the visual central. At companion width, use one inspected comparison view with both algorithm result selectors and place manipulation beside stepping. Keep the question composer reachable without a long scroll.
- An explanatory follow-up preserves scientific controls. When they change, use a current-experiment heading and retain earlier wording under source/history details. Never label stale prose as describing a new result.
- Numerical captions come from the displayed calculation, not global number matching in model text. Preserve units, exact values and tentative, floating, unreached or unrevealed states.
- Keep the last usable visual and typed draft during preparation, cancellation and failed save. Show Unsaved, Saving and Saved beside the save control; edits remain unsaved until confirmed.
- Keep source drawings aligned and stale-screen failures explicit. Do not point at a changed display or count a source marker as precise computer vision.
- Playback is interruptible. Manual stepping and captions work without audio; reduced motion settles to the checked snapshot. Audio progress is not word-level alignment.
- Optional prediction/practice is never a gate to exploration. Expose assistance/reveal state and retain the original response; do not show a mastery claim.
- General mechanisms and the built-in engine are illustrative. Camera/pose interaction must not imply a validated physical simulation.

## Visual and accessibility checks

Use the existing warm journal palette, typography and spacing; preserve the established look rather than introducing a last-minute redesign. Keep graph/circuit labels distinct from costs and avoid hiding values in small cut-off tags. Dense sources may need explicit zoom or recapture, not progressively smaller text.

Check 375px, 620px and desktop widths, keyboard-only operation, visible focus, reduced motion and no-WebGL fallback. Controls need meaningful names and a readable nonvisual state. Test actual generated/recorded content as well as prepared examples. Phone reflow does not establish readability of every word on a full-size lecture slide.

## Earlier course workspace

Existing Today, Map and Activity routes keep their established navigation and data. Source collection stays read-only; source facts, observations and interpretations remain distinct. Course setup must not block `/explore`. See [PRD](PRD.md) and [architecture](ARCHITECTURE.md) for the current boundary.
