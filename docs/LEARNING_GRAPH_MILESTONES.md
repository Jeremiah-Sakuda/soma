## Development scenario matrix

| Variation | Required evidence |
| --- | --- |
| Ambiguous returned work | Two defensible explanations with limits, or clarification when evidence is insufficient |
| First experiment uninformative | Validator rejects it; a bounded repair can find a useful comparison |
| Response contradicts the initial interpretation | Versioned reconsideration and a materially different supported next activity |
| Response remains ambiguous / existing activity still useful | Uncertainty or valid activity retained; no forced adaptation |
| Student disagrees or corrects transcription | Original observation retained; correction linked; interpretation reconsidered |
| Help, explanation, hypothesis or result exposed first | Truthful assistance/exposure conditions after restart |
| Source changes while work is queued | Obsolete publication rejected; unaffected valid work preserved |
| Retry, reload, account boundary, budget refusal | No duplicate/misattributed evidence; safe recovery and bounded model use |
| Fresh application | Different item/condition; no automatic cross-course mastery propagation |
| Image unreadable or topic unsupported | Explicit uncertainty/fallback; no fabricated region or flagship pass |

Freeze evaluation inputs before release runs and keep the existing five-reference numerical, 8/10 unseen supported-request, five negative-case, returned-work and privacy gates. Synthetic polish is a development milestone, not permission to remove them.
