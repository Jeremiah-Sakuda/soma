## What the stronger adaptation check establishes

The first activity was generated by Spark. The harness submitted the option opposing its first hypothesis through the actual `applyAction` attempt service, with no recorded help. That observation was ungraded. Spark then read the relevant course evidence, issued two explicit hypothesis-revision tools and selected a different ready lesson with a different question. Publication updated the recommendation and preserved the original records.

Both adaptive publications survived JSON serialize/reload. They were **in-memory engine publications**, not new managed-workspace persistence checks. The different post-response activity was already authored in the synthetic library; this run does not prove that Spark generated a new follow-up lesson after the response. Invocation was explicit for both stages; there was no background trigger or automatic post-answer job.

Source references in the authority case were already ingested, authorized records. The model chose the registered follow-up read. This is not browser computer use. Authority context was supplied by the synthetic fixture; normal ingestion still needs the production authority/context wiring identified in the audit.

These checks establish valid actions and preserved evidence in these cases. They do not establish scientific/instructional quality across subjects, actual learning improvement, robust all-course reliability or the PRD's full release gate. Earlier failures remain in [BUILD_LOG.md](BUILD_LOG.md); they were not erased or rerun as fresh evidence.
