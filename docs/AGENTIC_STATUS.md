## Where the model decides and the application enforces

Spark chooses `list_sources`, `read_source`, `follow_reference`, `evaluate_experiment`, `prepare_diagnostic`, `prepare_experiment_diagnostic`, `revise_interpretation` and `finish_investigation` in a bounded tool loop: [investigator.ts](../src/lib/server/investigator.ts#L24). It can retain a recommendation, select an existing lesson, or propose a new optional diagnostic. Registered references are links to already authorized, ingested records, not arbitrary external navigation.

The application validates ownership/course scope, exact disclosed citations, authority/conflict constraints, diagnostic discriminability, allowable hypothesis statuses given the actual response, source/model freshness, spend and publication. It computes circuit results and availability arithmetic deterministically. This is the intended safety boundary; deterministic checks are not evidence that model interpretation itself is deterministic or independently verified.

An original diagnostic response is ungraded and recorded without inferred diagnosis or automatic follow-up: [learning.ts](../src/lib/domain/learning.ts#L195). Supported/weakened status must agree with the saved response's declared prediction; Spark may conservatively retain uncertainty: [investigator.ts](../src/lib/server/investigator.ts#L125). The explicit follow-up invocation is [investigation-panel.tsx](../src/components/investigation-panel.tsx#L96). Ordinary MC authored follow-up is [learning.ts](../src/lib/domain/learning.ts#L219).

## Post-response proof boundary

The frozen-v4 held-out F1 case requires a new text diagnostic. F2 requires linked original evidence and valid hypothesis revisions, but **does not require** a new lesson, a changed question, or a changed recommendation: [held-out live test](../tests/providers/investigator-heldout-v2-live.test.ts#L132). The build log explicitly preserves this qualification and the earlier 1/4 failure result; the later 2/2 cases across four stages are not the complete PRD release gate.

P029 subsequently passed a fresh bounded simulated case that selected a different existing activity after a contrary response, preserving the original evidence through in-memory publication and JSON reload. It did not generate a new lesson in the second stage, run automatically, or exercise managed account persistence. See [the measured results](AGENTIC_EVALUATION.md).

To demonstrate the stronger remaining claim, a fresh bounded simulated case should capture: initial competing hypotheses and discriminating interaction → original contrary response through the ordinary attempt service → actual explicit Spark reconsideration → a newly generated supported next activity with a different question/objective or meaningful experiment change → persisted recommendation and reload, with old hypotheses, source versions, response and assistance intact. If Spark legitimately retains uncertainty/current work, record that outcome; do not relabel it as successful new-activity generation. Automatic invocation would require a separate implementation change and page-closed execution proof.
