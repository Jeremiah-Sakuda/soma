## Product and release priority

Soma is a desktop visual learning companion that turns what is on your screen into an explanation you can explore. PM049 adds the macOS companion; PM050 adopts this as the primary positioning. The web experience remains the immediate guest/judge entry. The core journey is selected window/screenshot → question → Muse-generated visual composition → meaningful manipulation → contextual follow-up → saved exploration. Source setup, full-semester ingestion and institutional login are optional background capabilities, and no longer launch prerequisites. Existing Today, Map, Activity, accounts, sources and working lessons remain available.

One checked family is breadth-first search on small unweighted graphs. Original synthetic examples establish the first slice; suitability for the owner's actual course must be checked separately. Explicit node order, direction, visited-on-enqueue behavior and termination-on-goal-dequeue define the model. A* and additional scientific families are deferred. Broader visual explanations carry explanation-only assurance; unsupported/illegible requests can ask for clarification. Checked computation does not certify every generated sentence or establish a learning benefit.

## Architecture and invariants

- Keep the existing React/Next application, Firebase ownership, Firestore persistence and global budget ledger. Add an exploration entry and bounded server pipeline; no agent framework, graph database or native overlay.
- Spark reads one explicitly selected image, extracts a candidate graph/interpretation, receives application-computed search feedback, and composes approved panels, node positions, highlights, state views and narration. A follow-up may revise focus, explanation or a supported comparison. This is model-authored composition; the renderer and computational rules remain authored application code.
- Strict scene specs contain no executable code, HTML callbacks, arbitrary resource URLs, credential access, learner-evidence writes or model-supplied verification/results. Application services bind authoritative source versions and derive assurance.
- Account exploration documents live under the owned account generation and participate in existing deletion fencing. Anonymous explorations use a separate short-lived HttpOnly capability and bounded guest persistence, not the v1 synthetic-workspace serializer. Concurrent publication requires the current revision/lease; cancellation cannot publish late content.
- Raw screenshots/audio are transient by default. Persist authorized derived observations, artifact versions, control state and concise run facts; do not log media bytes, private provider text or internal reasoning. Captures are sent only on Ask/Refresh, and sharing can be stopped. Provider retention is a separate policy boundary.
- Reuse global inference reservations and actual usage settlement. Each visual turn has bounded calls, time, payload, scene complexity and repair count, with a conservative per-call headroom check. Guest admission/concurrency limits supplement the shared global cap. P084 allows a testing cap up to $5 if the existing allowance is exhausted; do not reset ledger consumption or the 20-percent allocation reserve.

## Voice and browser boundaries

## PM047 — Checked motion stage (October 29)

The BFS renderer combines graph and queue in one SVG coordinate system. A node leaves the queue and travels to its graph position; each newly discovered connection is traced before that node moves into the back of the queue. Existing queue members shift forward continuously. Goal paths reveal only at the actual found snapshot. Every action is derived from the checked execution and current controls, including directedness, cycles, changed starts, removed edges and neighbor order. Motion changes no source, simulation rule, saved experiment state or learning evidence.

Gemini playback uses the real audio element's currentTime/duration to drive bounded visual beats within the current step; progress is bound to the artifact/version/view so old progress cannot drive the next scene. Step advancement still requires the actual ended event. This is proportional scene timing, not word-level alignment. Browser speech uses static checked snapshots because its timing callbacks are inconsistent. Manual changes replay a 2.4-second transition, while pause settles to the checked result and reduced motion displays that result immediately. The next-step audio cache and cancellation behavior are retained.

One checked graph fills the presentation row; a matching standalone frontier becomes a screen-reader state alternative because the same queue is visible within the stage. Comparison graphs retain their distinct queues and shorter traces hold at their actual final state. Positions fit the generated layout into the stage without changing relationships; phone layouts use a narrower coordinate system and four queue slots per row. Generic explanation diagrams gain progressive node/connection reveals through the same bounded renderer. Spark continues to author diagram objects, positions, highlights, narration and explanatory structure; the motion rules remain application-authored and do not create new quantitative capabilities.

New acceptance: intermediate frames show dequeue → trace → enqueue in checked order; no fabricated discovery on cycles or premature goal path; actual audio progress drives poses without stale-step flashes; manual changes interrupt cleanly; reduced motion is static; phone labels and queue remain contained. No new provider call, model family, arbitrary code generation or budget increase is required by this renderer. Full 3D, custom mechanics outside BFS and precise word timing remain outside this iteration.
