Use the canonical `Jeremiah-Sakuda/soma` repository and this working folder. The repository is public with user authorization. ## Product and implementation

Start with [CODEX_HANDOFF.md](CODEX_HANDOFF.md), [PRD](docs/PRD.md) and [implementation map](docs/SOMA_V2_IMPLEMENTATION.md). Documentation-only work does not authorize scaffolding or new features. Before UI/UX work, read [UI_UX_GUIDE.md](docs/UI_UX_GUIDE.md). Preserve the established journal, verified behavior and accessible alternatives.

The primary journey is selected visible context → generated visual → checked manipulation → contextual follow-up → saved revision. Course setup and full-semester collection must not block it. Preserve earlier routes, data and read-only source collection. Architecture decisions belong in [docs/DECISIONS.md](docs/DECISIONS.md); executed evidence belongs in [docs/VERIFICATION.md](docs/VERIFICATION.md).

- Soma is the product/agent; Spark is the runtime Meta model. The consumer Muse study workflow is the origin story.
- Spark interprets/proposes; typed application contracts and deterministic solvers compute consequences. Wonder checks are fallible and their actual status must remain visible.
- Checked families are nonnegative BFS/Dijkstra graphs and ideal DC circuits within documented limits. Other subjects and the built-in engine remain illustrative/explanatory. Do not add a topic or model merely for breadth.
- Preserve current scientific controls and original source/version lineage through follow-ups and saving. Generated wording cannot silently reset the experiment or replace computed facts.
- Store observations separately from interpretations. Preserve original attempts, assistance, versions, uncertainty and actual time. Exploration, completion and assisted answers cannot become independent-understanding evidence.
- Use bounded typed specifications. Generated content cannot execute arbitrary code, access credentials, write evidence directly or change validation rules.
- Enforce ownership at HTTP, storage, jobs, sessions and tool boundaries. Recheck versions/generations before publication. Make retried work idempotent.
- Keep private screenshot pixels transient and credentials, sessions, private coursework and learner records out of source/demo assets. Preserve recording provenance and third-party notices.
- Bound bytes, calls, tokens, retries, wall time, concurrency and spend. Unknown usage retains its reservation. Keep 20% of the actual Meta allocation reserved; provider alerts do not replace application limits.

Use the pinned TypeScript stack and managed Firestore, with an explicit synthetic local fallback. Do not add a graph database or agent framework without a demonstrated need. Follow installed Next documentation before changing framework code.

## Working records and verification

Maintain local ignored `docs/BUILD_LOG.md` and `docs/build-log/prompts.json`; never re-add them or cite them as published evidence. Read recent local entries when resuming. Capture human prompts/clarifications verbatim with stable IDs and actual timestamps when available; do not invent missing timestamps. Exclude platform-injected/inter-agent messages. Redact credentials/private data explicitly rather than creating another secret archive. For each prompt record the top three material outcomes, pending/unverified results and deviations; update outcomes before ending. Keep private planning drafts and capture material local.

Run meaningful numerical, state, ownership, recovery and user-journey checks. Preserve failed attempts and distinguish actual providers from doubles, recordings, prepared examples and simulated time. Do not fabricate model reasoning, activity or test outcomes. Check target viewports, keyboard-only use, reduced motion and no-WebGL fallback. Never treat a source build as hosted/native acceptance. Regenerate and verify the runtime manifest after runtime changes.

The submission deadline is November 4, 2026, 9 PM America/New_York. Preserve the correctness and polish gates; no unrequested model-count or scope expansion.
