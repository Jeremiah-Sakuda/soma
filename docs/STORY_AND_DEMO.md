# Soma — the story we are telling

PM129 · November 1, 2026. Current narrative for the demo, README and submission. This supersedes the [historical PM070 draft](archive/PM070_STORY_AND_DEMO.md). The product scope remains in the PRD; this is a framing change, not a new feature commitment.

**Turn what you’re studying into something you can explore.**

Soma is a visual learning companion. It takes selected material and a question, then uses Meta’s Muse models to build an interactive explanation. A student can change a connection, inspect a moving part, ask about the consequence and keep the exploration.

## The human problem

The material is already in front of you: a lecture diagram, a worked example, a technical document. The question is specific: “What if I change this?” Turning that question into an experiment often means translating the example into another tool, rebuilding it or looking for a demonstration that happens to match.

Soma’s opportunity is to reduce that setup. Bring an explorable explanation to the material someone is already working on, at the moment they want to investigate it.

## The potential

Students and independent learners could move more easily from reading a fixed example to testing their own questions. The potential is less reconstruction and tool-switching, more direct exploration, and explanations that can follow the learner’s current experiment.

For this hackathon, make that opportunity tangible through a working interaction. The Impact criterion asks about potential, beneficiaries, significance, likely use and theme fit. A classroom study or measured learning gain is not a prerequisite. Do not invent numerical benefits; show why the capability could matter.

## The demonstration

Open with the engine: two matching piston positions, different stroke roles, one synchronized control. It is a fast visual reason to care. Then show Soma’s checked graph workflow: selected source → generated visual → changed connection → contextual explanation → saved revision. Return to the engine to show how far we pushed Muse’s authorship and investigation choices.

The two examples demonstrate complementary capabilities. Keep “Recorded engine prototype” visible in engine footage. The graph workflow proves the existing source/manipulation/revision/persistence loop. The engine shows actual recorded Muse-authored artwork and question-conditioned visual actions. Its local study download is distinct from a canonical saved exploration.

**The emotional arc:** curiosity → control → consequence → possibility.

**The technical idea:** Muse chooses how to interpret and explain; Soma constrains the interaction and independently computes supported graph results. “The model proposes; the code proves” applies to those checked computations, not every scientific claim in an illustration.
